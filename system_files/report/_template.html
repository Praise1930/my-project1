02 Defects found and fixed

Ordered by severity. Each was reproduced before the fix and re-verified after, with the compiler, linter, and build re-run clean.

Realtime re-subscription crashed the entire application

Critical Fixed

src/services/syncService.ts — SyncService.init()

The Supabase client caches channels by topic and outlives the module that created them. When init() ran a second time against a cached channel that had already been subscribed, registering postgres_changes handlers threw cannot add postgres_changes callbacks … after subscribe(). Nothing caught it, so the error propagated out of <App> and — with no error boundary in the tree — unmounted the whole interface. A responder would have been left staring at a blank screen mid-emergency.

Fix: any stale channel on the mamatrack-sync topic is removed before a fresh one is built, and the whole subscription is wrapped so that losing realtime degrades to queue-and-poll sync instead of taking the app down. Raising an SOS never depends on the live channel.

A corrupt offline queue permanently stranded every pending edit

Major Fixed

src/services/syncService.ts — enqueueOfflineChange(), flushOfflineQueue()

Both functions called JSON.parse on the queue with no guard. Because the queue lives in browser-writable local storage, a single malformed value would throw on every subsequent flush — so work captured offline in a rural area would never reach the server, silently and permanently.

Fix: a shared readQueue() helper that tolerates a bad parse, resets the corrupt entry, and warns, so the next flush proceeds.

Failure paths reported success

Major Fixed

src/services/db.ts (×3), src/pages/MotherDashboard.tsx

Four catch blocks logged a success message on the error path — a failed cross-tab broadcast printed "Broadcast channel event posted", and a failed SOS siren printed "Audio alert notification sound played". Anyone reading the console during a demo or a defence would have been told the opposite of what happened, and the underlying error was discarded.

Fix: each now warns and includes the real error.

A non-array offline cache could discard a queued SOS

Minor Fixed

src/services/offlineStorage.ts — getQueuedEmergencies()

The function returned whatever JSON.parse produced. A stored object rather than an array would make the callers' .push() and .filter() throw, losing the queued emergency. Fix: the shape is now guarded as well as the parse.

52 lint warnings, including a Fast Refresh violation

Minor Fixed

Across 11 files

47 uses of any were replaced with real types — a SyncedRow contract for everything crossing the sync boundary, MotherWithContact and Notification in the VHT portal, typed CustomEvent payloads, as const navigation arrays that make each tab id check against its portal's union, and a properly typed fallback for Safari's prefixed webkitAudioContext. Four unused catch bindings were removed.

Toast.tsx exported both a component and a function, which breaks React Fast Refresh: every edit remounted the module and dropped dashboard state mid-test. The event bus now lives in toastBus.ts and Toast.tsx exports only its component.

03 Known limitations left in place

These are design consequences rather than accidents. Changing any of them alters how the system behaves, so they are documented for the decision rather than changed silently.

Row Level Security is enabled but fully permissive

Security Open

supabase_schema.sql

The schema enables RLS on every table and then attaches a single policy — FOR ALL USING (true) WITH CHECK (true). Since the anonymous key ships to the browser, anyone who loads the site can read and write every table, including users. That is workable for a demonstration seeded with fictional patients, but it must be tightened before the system holds a real mother's record.

Recommended: move accounts into Supabase Auth, then key policies to auth.uid() and role — a mother reads only her own rows; a driver reads only the emergency assigned to them; an administrator reads the district.

Authentication is local-first

Security Open

src/pages/Login.tsx

Login tries Supabase Auth first and falls back to the local seeded store. The demonstration accounts do not exist in Supabase Auth, so that first attempt returns 400 on /auth/v1/token — the one error visible in a clean console. It is handled and intentional, but it means passwords for seeded accounts are compared on the device rather than by the identity provider.

No React error boundary

Resilience Open

src/App.tsx

Finding 1 was severe precisely because there is nothing between a thrown render error and a blank page. The specific trigger is fixed, but a boundary around the routed portals would contain the next one and let a responder retry rather than reload.

The offline storage module is not wired in

Documentation Open

src/services/offlineStorage.ts

The module exists and is now hardened, but nothing imports it. Offline behaviour in the running system is provided by SyncService's queue, which captures changes when the network drops and replays them on reconnect. Any documentation describing offlineStorage as the live offline path overstates it — either wire it in or describe the queue instead.

Also noted

React Router prints two v7 future-flag warnings (v7_startTransition, v7_relativeSplatPath). They are advisory. Opting in changes routing behaviour, so it is a deliberate upgrade step rather than a fix, and was left alone.

08 Assessment

The system builds clean, runs clean, and the emergency pathway works across devices. What remains is a security posture appropriate to a demonstration rather than to patient data.

The most consequential finding was not a compiler error — the compiler was already silent. It was a realtime subscription that could throw during startup and, with no error boundary to catch it, take the entire interface down. That class of defect is invisible to static analysis and only appears when the running application is exercised, which is why the check included a live emergency rather than stopping at a green build.

Before the system carries a real mother's record, two things should change: the permissive Row Level Security policy should be replaced with policies keyed to authenticated identity and role, and accounts should move into Supabase Auth so that credentials are verified by the identity provider rather than compared on the device. An error boundary around the routed portals is a small addition with a large effect on resilience in the field.

Nothing in this report blocks a demonstration or a defence. The fixes applied are behaviour preserving except where the previous behaviour was a crash or a false success message.
